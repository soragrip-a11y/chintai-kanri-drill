# LoopQ independent review — 2026-10-14

Status: **NOT RELEASE-READY**. This document audits the locally produced `loopq-v2` preview and the earlier public site. Adding documentation/skills does **not** deploy the new LoopQ UI or activate ChatGPT inference.

## Critical findings

1. **No available hosted-Web plan-sharing integration.** Sign in with ChatGPT identity and the separate delegated *plan-usage* capability are different. OpenAI's open-source documentation is for locally hosted apps; remotely hosted websites need appropriate partner access. Inference must stay disabled until eligibility, scopes, user consent, token storage and actual calls are verified. Sources: https://developers.openai.com/siwc/token-sharing-open-source ; https://developers.openai.com/siwc/website .
2. **AI feature is deliberately disabled.** The preview `app.js` throws in `generate()`, and UI's generate buttons do not perform generation. Never describe this as a working AI app.
3. **Untrusted import HTML injection exposure.** In the preview, `importBackup` accepts loosely validated JSON, and `sourceCard` interpolates `r.image` into raw HTML attributes. A malicious image value could escape the `src` attribute. Sanitize strictly and use DOM APIs before allowing backup import from third parties.
4. **No verified production migration** from the earlier 50-question application. Main public branch still hosts the earlier application at audit time. Do not claim the new UI has gone live.

## High findings

5. **Storage scaling is not addressed.** Full image base64 strings are stored in every record; `refresh()` loads all records and images into memory. At 100 KB/photo, 1,000,000 photos would require approximately 100 GB before base64/metadata overhead, which is not a realistic single-mobile-browser assumption. Even 1,000–10,000 images require redesign: blobs, lazy loading, paging, capacity indicator and export format redesign.
6. **Backup fragility.** Single huge JSON export, 75 MB import cap, partial record writes on failed restore, non-atomic mutation, weak schema checks and no checksum/merge preview. Device/browser storage clearance permanently deletes unexported work.
7. **Unverified exam answers.** AI crosschecking alone is not an independent authority; there is no proven current-law corpus, confidence gating or subject matter reviewer. Proposed 3 yes/no questions often fail to match actual multiple-choice exam forms.
8. **Misleading UI remnants.** `home()` references `settings.endpoint` even though operator API settings were removed. AI generate calls present a button but cannot work. Some code after unconditional return is unreachable.
9. **Unused paid-worker source contradicts no-owner-billing policy.** A separate development `worker/` folder still contains an operator-key OpenAI gateway and shared access code. It is not included in the later local-first preview ZIP, but must not be deployed inadvertently.
10. **Browser testing coverage gap.** `browser_mock.py` and worker mock tests passed; `smoke.py` cannot navigate the local file in current environment (administrator blocks it). No physical iPhone Safari/PWA test evidence.

## Medium findings

11. No exact image type support guarantee for HEIC, even if advertised. No photo rotation/crop/redaction/poor-image feedback.
12. No account-independent meaningful export of the *new* App schema across devices. Early beta requires migration and backup UX.
13. User-supplied images may contain copyrighted text and personal data. Local photography and AI transmission are distinct legal/processing contexts; require clear consent and terms, avoid redistribution and lightly rewritten originals.
14. Public UI currently says `PRIVATE LIBRARY` but the data is not encrypted at rest by the application. Device protection and optional backup encryption may be necessary for sensitive photos.
15. Web accessibility and usability haven't been independently verified for assistive tech; mobile design test alone is insufficient.

## What is actually verified

- Local preview files exist; front-end mock tests report desktop/manual/review OK, mobile overflow OK.
- Three Cloudflare Worker mock tests pass. This **does not** imply live OpenAI integration or legal answer accuracy.
- Actual hosted app approval, full image workflow, on-device persistent storage under pressure, copyright compliance and legal item review: **not verified**.

## Recommended sequence

P0: Keep main production untouched and retain rollback. Verify Sign in with ChatGPT hosted-Web eligibility, remove paid-worker path from a future production bundle, fix import XSS/validation.
P1: Redesign local images as binary blobs with lazy thumbnails and durable, verified backup. Add iOS Safari tests and data migration. Establish a gold-standard exam QA set with primary-law sources, exam-year cutoff and legal review flag.
P2: Make course-neutral question families and retention UX; pilot with 10–30 real learners. Measure fact accuracy, exam difficulty parity, 7-day return rate, cost per accepted question and data recovery rate before scaling.
